# 코드 설명 주석 추가

각 함수의 역할과 주요 API 또는 코드 블록의 사용법을 함께 이해할 수 있는 주석을 추가한다. 프로그램의 동작을 보존하고 사용자와 저장소에서 사용하는 언어를 따른다. 한국어 요청에는 한국어 주석을 사용한다.

## 작업 절차

1. 대상 파일 전체와 코드를 이해하는 데 필요한 타입, 스키마, 설정, 주변 예제를 읽는다.
2. 함수의 경계와 동작, 제약, 반환값 또는 설계 의도가 명확하지 않은 주요 코드를 찾는다.
3. 아래 기준에 따라 함수 설명 주석과 주요 코드 설명 주석을 추가한다.
4. 중복되거나 오래되었거나 현재 구현과 맞지 않는 주석은 제거하거나 고친다.
5. 실행 코드가 변경되지 않았는지 확인하고, 가능한 경우 포매터, 타입 검사 또는 문법 검사를 실행한다.

## 함수 설명 주석

중요한 함수 위에 JSDoc 주석을 작성하고 다음 내용을 설명한다.

- 함수가 수행하거나 보여 주는 작업
- 해당 방식을 사용하는 이유와 적절한 사용 시점
- 중요한 관계, 트랜잭션, 부수 효과 또는 반환값의 특징
- 학습자가 알아야 하는 제약이나 실패 조건

파일이 순서대로 실행하는 예제 또는 튜토리얼일 때만 번호를 붙인다. 함수의 전체 목적과 코드 내부의 세부 API 설명이 중복되지 않게 작성한다.

```ts
/**
 * 2) nested create: User와 Post를 한 번에 생성
 *
 * 관계 데이터까지 함께 생성해야 할 때 사용하는 대표적인 nested write입니다.
 * include를 사용하면 생성된 User와 Post를 한 결과로 받을 수 있습니다.
 */
```

## 주요 코드 설명 주석

주석은 설명 대상 코드 바로 위에 작성한다. 다음과 같은 주요 호출과 의미 있는 옵션을 중심으로 설명한다.

- ORM, SDK, 프레임워크, 파일 시스템, 네트워크 또는 데이터베이스 작업
- `data`, `select`, `include`, `where`, `connect`, `createMany`와 같은 주요 옵션
- 자동 생성값, 기본값, 고유 제약, 외래 키 및 연쇄 삭제 동작
- 반환 형태, 부수 효과, 오류 동작, 정리 작업 및 자원 해제
- 여러 API 형태 중 현재 방식을 선택한 이유

두세 문장의 짧은 주석 블록을 우선한다.

```ts
// connect는 새 User를 만들지 않고 기존 User를 연결합니다.
// where에는 id, email 같은 unique 필드를 사용해야 합니다.
author: {
  connect: { email: authorEmail },
},
```

문법을 그대로 읽어 주지 말고 API의 사용 규칙을 설명한다. 예를 들어 `createMany`가 생성된 객체 대신 건수를 반환하며 중첩 쓰기를 지원하지 않는다는 점은 설명한다. 반면 “title에 제목을 넣습니다.”처럼 코드만 읽어도 알 수 있는 내용은 주석으로 작성하지 않는다.

## 주석 작성 기준

- 코드를 학습하는 개발자가 이해하기 쉬운 평이한 설명체를 사용한다.
- 한국어 주석은 `합니다`, `됩니다`와 같은 완결된 문장으로 일관되게 작성한다.
- 주석을 관련 코드 가까이에 배치하고 하나의 주석 블록에서는 한 가지 주제만 다룬다.
- 실제 동작을 먼저 설명하고 정확성을 높이는 경우에만 전문 용어를 사용한다.
- 선행 조건과 실패 가능성은 해당 조건에 의존하는 코드 가까이에서 설명한다.
- 유용한 기존 주석과 저장소의 코드 형식은 유지한다.
- 모든 줄, import, 단순 할당, 로그문 또는 자명한 속성에 주석을 달지 않는다.
- 같은 설명을 JSDoc과 코드 내부 주석에서 반복하지 않는다.
- 코드, 타입, 스키마 또는 공식 문서로 확인할 수 없는 동작을 단정하지 않는다.
- 사용자가 별도로 코드 변경을 요청하지 않았다면 이름, 제어 흐름, 쿼리, 값 또는 외부 동작을 변경하지 않는다.

## 완료 전 점검

작업을 마치기 전에 다음 항목을 확인한다.

- 각 중요 함수에 목적을 설명하는 간결한 주석이 있는가?
- 이해하기 어려운 주요 API 호출 가까이에 사용법을 설명하는 주석이 있는가?
- 모든 주석이 현재 코드의 동작과 일치하는가?
- 중복되거나 자명한 주석을 피했는가?
- 실행 코드가 변경되지 않았는가?
- 가능한 검증 과정에서 새로운 오류가 발견되지 않았는가?
